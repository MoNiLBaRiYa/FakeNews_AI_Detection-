--------------------------------------------------------------
TRUTHGUARD AI: TECHNICAL EXPLANATION & ARCHITECTURE
--------------------------------------------------------------

This document explains exactly how all the new and old features of TruthGuard AI work together, designed to be understood by non-technical team members and new developers alike.

=====================================
1. THE CORE ENGINE (How it detects fake news)
=====================================
TruthGuard is powered by Machine Learning (specifically, Logistic Regression running via Scikit-Learn in Python). 

Real World Example: 
Imagine you are a teacher grading essays. Over time, you notice that students who copy-paste from Wikipedia use certain words or sentence structures that sound "too formal" compared to their normal voice. 
Our ML model does exactly this, but for news. It has "read" thousands of real articles and fake articles. It learns mathematical patterns—like if an article contains excessive emotional trigger words, all-caps, or lacks formal journalistic vocabulary—it flags it.

When you paste text into the Analyzer:
1. The text is "cleaned" (removing punctuation, common filler words).
2. It's converted into numbers (TF-IDF Vectorization).
3. The Model looks at the numbers and spits out a probability (e.g., "I am 94% sure this is Fake").

=====================================
2. FACT-CHECK HISTORY
=====================================
What is it? A log of everything a user has verified in the past.
How it works:
When a user logs in and analyzes a piece of text, before the result is shown on the screen, the Backend Python code quietly takes that result and saves it into a MongoDB database. 

Real World Example:
Like your web browser's history, but for fake news. Because it's stored in a database in the cloud, if you log in from your phone later, you can click the "History" tab and see the exact same articles you checked on your laptop.

=====================================
3. SOCIAL LOGIN (GOOGLE OAUTH)
=====================================
What is it? Allowing users to bypass creating a password and just clicking "Sign in with Google."
How it works:
We use a library called `Authlib`. When a user clicks the Google button:
1. We send them to Google's official login page.
2. Google asks "Do you want to share your email with TruthGuard?"
3. The user says yes, and Google sends them back to our app with a secure "Token".
4. Our app reads the token, gets their email, and automatically logs them into our system.

Real World Example:
It's like showing your driver's license to a bouncer at a club instead of filling out a massive registration form. Google acts as the trusted government ID.

=====================================
4. LIVE THREAT MAP & TRENDS
=====================================
What is it? The interactive world map showing fake news outbreaks.
How it works:
We have two systems here:
1. News Scraper: Our backend constantly pulls real news from APIs (NewsData.io, NewsAPI) for different cities. It feeds that news into our ML model. If the model says it's fake, it drops a red pin on the map.
2. Threat Trends: We added a new `/api/threat-trends` endpoint. This looks at the database of recent checks and mathematically counts which words are popping up the most (e.g., "#ElectionFraud"). It then sends this list to the right-side panel of the Threat Map.

Real World Example:
Like a weather radar, but for misinformation. Instead of tracking rain clouds, it trackers clusters of "fake" predictions over certain geographic areas, giving journalists an early warning system.

=====================================
5. BROWSER EXTENSION
=====================================
What is it? A Chrome Extension that lets users check news without visiting TruthGuard.ai.
How it works:
We created a "Scaffold" (the foundational code) in the `BrowserExtension/` folder.
1. A user highlights text on Facebook or Twitter.
2. They right-click and select "Verify with TruthGuard".
3. The extension grabs the highlighted text and fires it invisibly to our new Developer API (`/api/v1/analyze`).
4. Our backend analyzes it and fires the result back to the browser as a popup alert.

Real World Example:
It's like having a miniature, invisible TruthGuard AI assistant sitting on your shoulder while you surf the web, ready to jump in whenever you ask it to look at something suspicious.

=====================================
6. DEEPFAKE / IMAGE DETECTION
=====================================
What is it? The ability to upload an image to see if it was manipulated by AI.
How it works (Currently Simulated for Phase 2):
Building a real Deepfake CV (Computer Vision) model takes immense processing power. For this stage, we built the Full UI (the Drag & Drop tab on the Analyzer) and the backend communication route (`/analyze_image`). Currently, the backend simulates the CV scan and returns a mock result (e.g., "Lighting artifact detected in left eye"). In Phase 3, this route will be connected to an actual Convolutional Neural Network (CNN).

=====================================
7. PRODUCTION READINESS (DOCKER & CACHING)
=====================================
We upgraded the engine room to handle thousands of users.
1. Caching: If 100 users in Ahmedabad open the Threat Map at the exact same time, the server used to scrape the web 100 times (which crashes servers). Now, it scrapes the web ONCE, saves the result in temporary memory (Cache), and just hands the exact same saved copy to the other 99 users instantly.
2. Gunicorn/Docker: We moved the app from a "Development Server" (like a test-drive track) to "Gunicorn" (a highway). It allows multiple workers to run the app simultaneously so it never freezes if traffic spikes.
